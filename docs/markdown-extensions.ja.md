# Markdown 拡張仕様（実装済み）

Mycel の Markdown プレビュー（プレビューペインとファイル名下のインラインカード）が解釈する記法のうち、CommonMark / GitHub Flavored Markdown に含まれない拡張をまとめます。0.10.1 時点の実装に基づきます。

## 1. 描画経路

Markdown は内容に応じて 2 つの経路で描画されます。どちらの経路でも本書の記法はすべて解釈されますが、表現できる範囲が異なります。

| 経路 | 条件 | 実装 | 特徴 |
| --- | --- | --- | --- |
| 通常（QTextEdit） | Mermaid 図・TeX 数式を含まない | Qt の Markdown 取り込み + 前後処理（`src/markdown_line_breaks.h`、`src/markdown_document.h`） | 軽量。カードはテキストのままスクロール・文字選択が可能 |
| 拡張（QtWebEngine） | ```` ```mermaid ```` フェンス、または `$…$` / `$$…$$` / `\(…\)` / `\[…\]` を含む | 同梱の markdown-it + mermaid.js + KaTeX（`src/tree_model.h` の `markdownToRichHtml()`） | プレビューペインでは直接描画。カードでは画像化して `.mycel/md-thumbnails` にキャッシュ |

Alert とルビの有無は経路の選択に影響しません。長い文書にルビや Alert があっても、カードはテキスト表示のままです。

## 2. 改行

本文中の改行は「その位置で折り返す」として表示します（CommonMark の「次の行につなげる」ではありません）。空行が段落の区切りです。

```markdown
一行目
二行目

次の段落
```

- 行末のスペース 2 つや `\` による従来のハード改行もそのまま改行として扱われ、二重にはなりません。
- 対象外: コードブロック（フェンス・インデント）、表、見出し（`#` 形式と setext 形式）、罫線、HTML ブロック、リンク定義行 `[id]: url`。
- リスト項目内の改行は同じ項目の中で折り返します。引用（`>`）の中も同様です。
- 拡張経路では markdown-it の `breaks` オプション、通常経路では取り込み前に行末へハード改行を付け、取り込み後に段落余白の無い行区切りへ結合し直す処理で実現しています。

## 3. GitHub Alerts

引用ブロックの先頭行に `[!TYPE]` を置きます。種類は大文字の 5 種類だけを認識し、小文字（`[!note]`）は通常の引用として表示します。

```markdown
> [!NOTE]
> 補足情報

> [!TIP]
> ヒント

> [!IMPORTANT]
> 重要事項

> [!WARNING]
> 警告

> [!CAUTION]
> 危険
```

- 本文は通常の Markdown として解釈します。複数段落（`>` だけの行で区切る）、リスト、強調、インラインコード、リンク、ルビを含められます。
- 表示: 拡張経路ではアイコン付きタイトルと色付きの枠（`<aside class="markdown-alert markdown-alert-note">`）。通常経路では太字・アクセント色のタイトルと背景色付きの引用ブロック（Qt の文書には左縦線を引く手段が無いため、縦線はありません）。
- タイトルは GitHub と同じ英語表記（Note / Tip / Important / Warning / Caution）です。
- 色は GitHub のパレット（ライト / ダーク別）を `src/markdown_document.h` の `markdownAlertColors()` で一元管理し、両経路で共有しています。
- Alert の入れ子は非推奨です（GitHub 同様）。

## 4. 青空文庫形式のルビ

### 基本形（省略形式）

```markdown
吾輩《わがはい》は猫である。
耳まで火照《ほて》って
```

`《` の直前に連続する漢字がルビ対象です。`々` `仝` `〆` `〇` `ヶ` は漢字として扱います。直前が漢字でない場合（`かな《よみ》`）は通常テキストのままです。

### 対象範囲の明示

```markdown
武州｜青梅《おうめ》の宿
孤立語・|膠着語《こうちゃくご》・屈折語
```

区切り記号は全角 `｜`（U+FF5C）と半角 `|`（U+007C）のどちらでも使えます（青空文庫の公式仕様は全角のみですが、入力しやすさのため半角も受け付けます）。`《` に最も近い区切りが開始位置です。明示形式は省略形式より先に判定します。

### 解釈しない場所

- インラインコード `` `青梅《おうめ》` `` とコードブロック内は変換しません。
- 閉じ `》` が無い場合（`青梅《おうめ`、`｜青梅《`）は通常テキストのままで、エラーにはなりません。

### 表示

- 拡張経路: HTML5 の `<ruby>青梅<rp>（</rp><rt>おうめ</rt><rp>）</rp></ruby>`。読みが親文字の上に表示されます。
- 通常経路: Qt の文書にはルビが無いため、独自のインラインオブジェクト（`src/ruby_text_object.cpp` の `RubyTextObject`）を登録し、親文字の上に半分の大きさで読みを描画します。行の高さは読みの分だけ広がります。内部的には Unicode の行間注釈文字（U+FFF9 / U+FFFA / U+FFFB）で取り込み、取り込み後にオブジェクトへ置き換えます。オブジェクトは 1 文字（U+FFFC）として扱われるため、プレビューからコピーした文字列にはルビ部分の文字は含まれません。

### 注意

- 表の中で半角 `|` はセル区切りとして先に処理されるため、セル内で明示形式を使うには全角 `｜` が必要です。

## 5. Mermaid 図と TeX 数式（拡張経路）

````markdown
```mermaid
graph TD; A-->B
```

インライン数式 $x^2$ とブロック数式

$$E=mc^2$$
````

- 数式は Markdown 解析前に退避し、KaTeX で描画します。インラインコードとコードブロック内の `$` は数式にしません。
- `$10 and $20` のような価格表記は数式とみなしません（開き `$` の直後が数字・空白の場合を除外）。
- 拡張経路のカード画像は幅 460px・高さ上限 900px で描画し、余白を切り取ってキャッシュします。キャッシュキーには更新日時・サイズ・テーマに加えてレンダラーの改訂番号（`kMarkdownRendererRevision`）が含まれ、描画ロジックを変えたときに番号を上げると再生成されます。

## 6. 処理順序

拡張経路（markdown-it）:

```text
Markdown 入力
  ↓ 数式の退避（コード外のみ）
  ↓ ブロック解析（markdown-it）
  ↓ GitHub Alerts（引用ブロックの先頭段落を判定）
  ↓ インライン解析
  ↓ ルビ（テキストトークンだけを対象）
  ↓ HTML 生成、数式の復元（KaTeX）、Mermaid 描画
```

通常経路（Qt）:

```text
Markdown 入力
  ↓ ルビ記法 → 行間注釈文字（コード外のみ）
  ↓ Alert 行を独立段落化
  ↓ 段落内の行末へハード改行を付与
  ↓ QTextDocument::setMarkdown()
  ↓ ハード改行のブロックを結合（行区切りへ）
  ↓ 注釈文字 → ルビオブジェクト（読みを上に描画）
  ↓ Alert のタイトル・背景色
```
